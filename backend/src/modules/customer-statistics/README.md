# STT122 customer statistics

Admin-only `GET /api/admin/customer-statistics`; read-only, no-store and audited without search text or customer PII. `from`/`to` use the Reports inclusive calendar range (default 30 days, maximum 366), fixed UTC+7; daily buckets up to 90 days, monthly thereafter. `search` is literal text, maximum 150 characters. `page`/`limit` (10, 20, 50) apply only to the locked-customer table. Every section is read from one repeatable-read, read-only transaction snapshot.

- Customers are current customer profiles joined to users, including people who also have a technician profile. ACTIVE, LOCKED and INACTIVE describe the current account state, not daily activity. With/without bookings use lifetime booking ownership.
- Acquisition uses customer profile registration dates. Comparison is the immediately preceding equally long period; growth is unavailable when the previous count is zero. Month/year counts run from the start of the month/year containing `to` through `to`.
- Areas use exactly one current default address per customer, following the existing address module's city/ward model. Optional district data from an older database is read through row JSON without requiring that removed column. The area key contains city, optional district and ward, so identically named wards in different cities remain separate. Missing default addresses, a missing city, or a missing ward/district form an explicit unknown bucket included in the percentage denominator. No fallback to historical or nondefault addresses. Top/average area metrics use known areas only. Fastest-growing area is unavailable when no known area's registration count increased, or its previous count is zero. New and previous registrations are assigned to their current default area; these are not historical address snapshots.
- Service usage includes only bookings whose current status is COMPLETED and whose **creation date** falls in the selected range. Bookings and customers are counted distinctly; service uses are booking-unit-service rows, including inactive historical services/categories. Percentages divide by all service uses. Service customer counts overlap and must not be added together. Repeat customers have at least two completed bookings in that same cohort.
- Cancellations use all bookings created in the range. Customer cancellation means current status CANCELLED with `cancelled_by_id` equal to the owner's user ID. Rejection means current status QUOTATION_REJECTED or at least one rejected quotation; multiple rejected quotations count once per booking. Technician matching DECLINED is excluded. A booking may be both cancelled and rejected; affectedBookings counts that union once. Trend dates are booking creation dates, not cancellation/rejection event timestamps.
- Locked rows show current account status and registration date only. The database does not establish a reliable lock date/reason, so neither is invented. No lock/unlock, appeal action, export, financial mutation or STT123 is provided.

Counts reject unsafe JavaScript integers. Ratios and averages are rounded to two decimals using integer arithmetic; zero denominators produce null, while empty distribution percentages are zero. Genuine zero results remain zero.
